# Contributing

Thank you for your interest. These rules apply to every repository under this account that
does not have its own `CONTRIBUTING.md`.

## Reporting a problem

1. Open an issue in the repository that has the problem. Pick the form that fits.
2. Say what you expected, and what happened instead.
3. Give the versions you use: the project's release, and Home Assistant or the host OS where
   that applies.
4. Attach the debug log of the failure. Remove passwords, tokens and your own addresses first.
5. For a Bluetooth device, also give its model, its firmware, and an advertisement capture if
   you can.

Do not report a security problem in a public issue. Read [SECURITY.md](SECURITY.md).

## How fast we reply

This is a part-time project with one maintainer. A reply can take a week. A quiet issue is
not a closed issue: it is still in the list.

## Pull requests

1. For a large change, open an issue first, so that we can agree on the approach.
2. Keep one pull request to one change.
3. Run the repository's own tests and linters before you open it. The CI runs them too.
4. Say how you tested the change, and on which device or version.

When we accept a pull request, we merge it on GitHub, so that you show as its author. Your
name stays in the history and in the release notes.

## AI assistance

Much of the code here is written with AI help. A person decides what is published and what is
released. Pull requests and release notes say what was tested, and what was not.

You may use AI tools for your own contribution. Tell us that you did, and tell us what you
checked yourself.

## Forks

Some repositories here are forks of another project. For a fork, report the problem upstream
first, unless it is in the changes this fork adds. The fork's README names its upstream.

## Code of conduct

Everyone who takes part agrees to the [code of conduct](CODE_OF_CONDUCT.md).
